# Хронограф. Принципы проекта

Система мониторинга строительной площадки для конкурса «Лидеры цифровой
трансформации 2026», задача №7. Постановщик — Департамент градостроительной
политики города Москвы, эксперты — ГАУ «Институт Генплана Москвы».

## Ради чего всё делается

Мы не детектируем технику на камере. Мы **превращаем видеопоток в
машино-часы** — нативную единицу календарного графика и сметы — и
автоматически сверяем фактические машино-часы с плановыми, выдавая
типизированные отклонения с доказательствами и прогнозом срыва срока.

Изменение, которое не приближает к этой формулировке, проекту не нужно.

## Правила разработки

1. **Контракты данных важнее кода.** Все модули общаются через схемы из
   `docs/02-data-contract.md`. При изменении схемы правится сначала
   документ, потом код, потом фикстуры в `data/benchmark/`.
2. **Каждый модуль запускается отдельно** на фикстурах, без камеры, без
   GPU, без интернета. `pytest` проходит на чистой машине.
3. **Демо не имеет права упасть.** Любая функция существует в двух
   режимах: `live` (реальная камера) и `replay` (предзаписанные снимки).
   Режим переключается переменной окружения `HG_MODE`, не правкой кода.
4. **Честность важнее красивых цифр.** При низком качестве кадра (ночь,
   дождь, залепленный объектив) система выставляет `confidence: low` и
   не формирует отклонение. Ложное отклонение обходится дороже
   пропущенного.
5. **Каждое отклонение объяснимо.** В карточке обязаны быть числа плана,
   числа факта, кадры-улики, ссылка на строку графика и формулировка на
   русском языке, понятная прорабу.
6. **Никаких заглушек в демонстрационном пути.** Если данных нет, они
   генерируются скриптом `scripts/make_synthetic.py` с честной разметкой,
   по которой можно посчитать метрики.
7. **Конфиденциальность.** Техническое задание конкурса конфиденциально
   (п. 6.3.4–6.3.5 Правил). Его содержимое в репозиторий не попадает.

## Технологический стек

| Слой | Технология |
|---|---|
| Детекция | Python 3.11, `ultralytics` (YOLO11n/s) |
| Трекинг | BoT-SORT (встроен в ultralytics) |
| Состояние «работает / простой» | признаки движения + логистическая регрессия (scikit-learn) |
| Аналитика | pandas, numpy |
| API | FastAPI + Pydantic v2 |
| Хранилище | SQLite (разработка) / PostgreSQL (продуктивный профиль compose) |
| Планировщик | APScheduler |
| Фронтенд | React 18 + Vite + TypeScript + Tailwind + shadcn/ui + Recharts |
| Запуск | Docker Compose, одна команда |

Стек менять без веской причины не следует.

## Структура репозитория

```
services/perception/  кадр -> детекции -> треки -> состояние   (detections.jsonl)
services/analytics/   детекции -> машино-часы -> матчинг -> отклонения -> прогноз
services/api/         FastAPI: объекты, камеры, зоны, график, отклонения, отчёты
web/                  React SPA, пять экранов
scripts/              синтетика, обучение детектора, сквозная оценка
notebooks/            обучение детектора и классификатора состояния
data/                 raw / interim / synthetic / benchmark / ref
docs/                 принципы, контракты, правила, метрики, питч
```

## Готовность задачи

- Код проходит `ruff` и `pytest`.
- Работает в режиме `replay` без сети и GPU.
- Обновлён соответствующий документ в `docs/`.
- Если задача про качество, обновлены цифры в `docs/04-metrics.md`.
  Числа берутся только из прогона `scripts/eval_end2end.py`.

## Терминология

Это язык заказчика, используется строго в таком виде.

- **МЧ** — машино-час. `mh_present` — часы присутствия, `mh_active` — часы
  работы.
- **КИТ** — коэффициент использования техники, `mh_active / mh_present`.
- **SPI** — индекс выполнения по срокам, факт МЧ к плану МЧ на дату.
- **Зона выполнения** — размеченный полигон на кадре, к которому привязана
  работа.
- **Ресурсный отпечаток** — ожидаемый состав и интенсивность техники для
  вида работ.
- **Отклонение** — типизированное расхождение факта с графиком, Р0–Р4,
  см. `docs/03-deviation-rules.md`.

## Осознанные ограничения области

- Не распознаём людей и не считаем нарушения охраны труда: это другая
  задача конкурса.
- Не строим трёхмерную реконструкцию и не сравниваем с BIM: слишком дорого
  на имеющихся сроках.
- Не читаем государственные номера техники.
- Не претендуем на юридически значимый учёт. Система даёт основание для
  проверки, а не заменяет её.
